## 场景真值 ground truth truth model

场景由真值生成器按目标编号逐个生成匀速直线目标，目标 i 的位置随时间 t 变化：

`x(t) = 100·i + (2 + 0.5·i)·t`，`y(t) = 60·i + (1 + 0.25·i)·t`，

其中 `t = 步序号 · timeStepSeconds`。

所以 1 号目标从 (100, 60) 出发、速度是每秒 (2, 1)，5 号目标从 (500, 300) 出发、速度是每秒
(4.5, 2.25)。目标之间没有机动、没有过程噪声、也没有相互作用，速度在整段运行里恒定。

## 观测生成 observation model sampling

对每个目标、每一步、每个配置好的观测源，依次做三件事：先以 `missingRate` 的概率决定这一步该源
是否产生观测（丢观测就什么都没有）；否则给该目标的位置加上每轴独立的高斯噪声，标准差为
`noiseStdDev`，即 `x + N(0, σ)`、`y + N(0, σ)`；最后把观测的置信度写入，供融合环节加权。

随机数的取用顺序是固定的，这也是同一 `randomSeed` 与 `simulationSteps` 能逐位复现整次运行的原因。

## 观测源类型 source types

观测源有且只有三种类型：`RADAR`（雷达）、`EO_IR`（光电/红外）和 `PRIOR_KNOWLEDGE`（先验知识）。

每个源有独立的噪声、缺失率、时延与置信度，所以一个多源场景实际上是在不同质量的数据之间做融合。
`PRIOR_KNOWLEDGE` 的置信度在内部会乘以 0.8，体现先验信息权重低于实测。

## 观测时延 delaySteps latency

`delaySteps` 表示该观测源报告的是目标 `delaySteps` 步之前的位置，也就是一个真实存在的时间延迟，
不是只做记录用的字段。观测上还会带一个 `observedTimeStep` 记录它实际对应的步。

时延对融合的影响是系统性的：延迟越大，观测与当前真值的偏差越大。给某个源设 0 步时延而给另一个源
设 5 步，本质上是在融合"现在"和"过去"的信息。要研究时延影响，每次只改一个源的
`delaySteps`。

## 平台能模拟什么、不能模拟什么 capability scope

当前场景是二维离散时间的合成环境，能模拟的目标行为限于匀速直线运动。平台不模拟目标机动、
编队、相互作用，也不模拟杂波、虚警，除 `missingRate` 之外没有漏检，没有目标的新生与消亡，
观测与目标的关联也不是按通用问题求解的。

因此这里得到的是**在已声明简化假设下**的相对结论，不适合直接当作真实雷达系统的性能数字。
